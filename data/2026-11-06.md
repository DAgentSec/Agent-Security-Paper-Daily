### [1] [SPILLWAY: Separating Target Admission from Sanitization to Defend Tool-Using Agents against Prompt Injection](https://arxiv.org/abs/2611.07222)
*Woosang Lim, Yeseul Chang, Jaewoo Lee*

Catalog: Agent Sec | Source: arXiv

TL;DR: SPILLWAY 通过读取工具的类型化返回值来判定动作目标是否来自用户任务，从而以确定性检查阻止注入指令把智能体动作重定向到攻击者目标。


<details>
  <summary>Details</summary>
Motivation: 工具型智能体可操作邮件、文件和支付，网页或共享文档中的隐藏指令可能诱导其把数据或资金发送给攻击者；现有运行时防御依赖模型做最终放行判断，既增加每步模型调用又可能受攻击文本影响，而溯源防御又需模型先规划或路由任务。

Method: SPILLWAY 利用“动作目标出现在工具类型化返回中、注入指令以自由文本出现”这一差异，建立无需逐任务计划的确定性底线：仅当工具输出中出现而用户任务中未出现的目标值，由只读工具以类型化字段返回，或被固定委托规则覆盖时才放行调用；确定性清洗器在模型读取前移除固定规则匹配的指令样区域并保留为证据，本地裁判可恢复被拒调用，但不能恢复目标位于被移除文本中的调用。

Result: 在三个骨干模型及其中一个上的七个任务套件中，标准模板化注入均未能将动作重定向到攻击者目标，SPILLWAY 在所测防御中取得最高平均效用和综合分数（NRP、ERS）；伪造聊天模板也直接为零，已发布强化学习攻击者的平均范围内攻击成功率为 .007；且无防御触发的骨干重跑、几乎不增加模型调用。

Conclusion: SPILLWAY 为个人 AI 智能体在动作目标上提供可审计的拒绝底线，在保持实用性的同时跨骨干模型成立。

Abstract: Tool-using agents act on email, files, and payments, so an instruction hidden in a web page or a shared document can make an agent send data or money to an attacker. Many runtime defenses put a language model on the decision that lets an action through, so the decision depends on a model that may read the attacker's text and adds model calls to every step. Provenance defenses keep the model off the final check but need a model to plan or route each task first. Where an action goes can instead be read from the tools' typed returns: an email's sender or a payment's account arrives in a typed field, while injected instructions arrive as free text. SPILLWAY turns this observation into a deterministic floor with no per-task plan. The check admits a call when each target value that appears in tool output but not in the user's task was returned by a read-only tool in a typed field or is covered by a fixed delegation rule. A deterministic sanitizer removes instruction-like regions its fixed rules match before the model reads them and retains the removed spans as evidence, and a local judge may restore a refused call, never one whose target lies in the removed text. Across three backbones, and seven task suites on one of them, no standard templated injection redirects an action to an attacker's target under SPILLWAY, at the highest observed mean utility and composite scores (NRP, ERS) of the defenses we run under that attack. A forged chat template also produces a raw zero, and mean in-scope attack success under a released reinforcement-learning attacker is .007. SPILLWAY reaches this floor with no defense-triggered backbone re-run and almost no added model call. As personal AI agents act on users' email, files, and payments, SPILLWAY gives them an auditable refusal floor on where their actions go that keeps them useful and holds across backbones.

### [2] [Beyond Instruction Override: Benchmarking Indirect Prompt Injection with Task-Tampering Attacks](https://arxiv.org/abs/2611.07640)
*Rongting Zhang, Martin Bertran, Sandeep Avula, Chia-Jung Lee, Vanessa Murdock*

Catalog: Agent Sec | Source: arXiv

TL;DR: 该文以“来源是否被授权决定某决策”而非“是否像指令”来界定间接提示注入（IPI），并构建基准证明攻击可篡改进行中任务的关键决策，而非重定向任务。


<details>
  <summary>Details</summary>
Motivation: 现有IPI基准多测试将工具智能体引向攻击者指定任务的重定向攻击，却忽略了不改变任务、只篡改任务结果的情形（如买家在纠纷证据中引用虚假退款政策抬高退款额）。这类“任务篡改”攻击未被充分评估，可能使防御效果被高估。

Method: 以权威边界定义攻击：植入内容试图影响其来源无权决定的决策即为攻击。构建含90个已验证案例、覆盖三个工具使用环境的基准；每个案例的用户请求明确指定解决目标决策的权威来源，攻击均篡改良性任务所必需的决策而非替换任务，并针对智能体决策的六个环节（目标、决策规则、可用动作、预期后果、观察解读、状态信念）设计同一有害结果的不同变体。

Result: 无防御时，针对决策规则、可用动作和状态三类目标的攻击在五个LLM上的平均成功率高于针对目标的攻击；检测-移除防御将目标攻击成功率降至2.4%，但观察与状态攻击仍分别达9.5%与12.1%，检测优化改写后差距依旧；工具策略防御仍有15.4%攻击成功率，接近无防御的17.0%，因为此类攻击通常保留预期工具、仅操纵执行中获取的数值。

Conclusion: 仅测试任务重定向或只针对智能体目标的评估会高估防御覆盖面；应按权威边界与决策环节设计基准，重点覆盖观察解读与状态信念等易被忽视的攻击面。

Yet attacker-controlled content can instead tamper with the outcome of the task already in progress. A buyer's dispute evidence can cite a false refund policy to inflate a refund without changing the task. We define IPI by authority rather than instruction-like wording: planted content constitutes an attack when it attempts to influence a decision that its source is not authorized to determine. We introduce a benchmark that makes this boundary explicit: in each of 90 validated cases across three tool-use environments, the user request specifies the source that resolves the targeted decision. Every attack tampers with a decision required by the benign task rather than replacing that task. Each case has attacks with the same harmful outcome that target up to six parts of the agent's decision making: its objective, decision rules, available actions, expected consequences, reading of observations, or beliefs about the current state. A tool-policy defense still allows 15.4% attack success, close to 17.0% without a defense, because these attacks generally retain expected tools and manipulate values obtained during execution. Evaluations whose attacks redirect the task or target only the agent's objective can therefore overestimate the coverage of these defenses. Code and data are available at https://github.com/amazon-science/task-tampering-prompt-injection.

<details>

*Tianming Sha*

TL;DR: Octopus 是一个单模型多智能体强化学习框架，通过共享主干模型和 GPU 驻留 KV-DAG 协调并行分支，在提升多智能体搜索推理准确率的同时显著提高训练吞吐并降低 KV 内存。


<details>
  <summary>Details</summary>
Motivation: 现有多智能体 LLM 框架在并行搜索时会在不同分支间复制前缀 KV 缓存，通过重新预填充文本摘要交换信息，并在强化学习中扁平化或丢弃跨分支依赖，导致计算与内存开销高且协作结构失真。

Method: Octopus 让所有线程共享一个主干模型，并通过 fork、read_thread、wait_threads、rewind、commit 五个原语在 GPU 驻留的 KV 状态 DAG 上协调。其包含三个协同机制：Zero-Copy Radix Forking 以 O(1) 游标视图在共享物理 KV 页上创建分支；Attention-Only KV Mounting 将兄弟线程终端 KV 块直接挂载到全注意力层并绕过线性递归状态；Packed DAG-GRPO Trainer 将各回合分支打包为一次块稀疏注意力计算，并用留一分支边际奖励分配反事实分支 credit。

Conclusion: Octopus 通过共享 KV-DAG、零拷贝分支和 DAG-GRPO 训练，将多智能体并行探索转化为高效的单模型强化学习过程，在准确性、训练效率和内存效率上均优于现有单智能体与文本摘要多智能体方案。

However, existing multi-agent frameworks duplicate prefix KV caches across branches, exchange findings by re-prefilling text summaries, and flatten or drop cross-branch dependencies during reinforcement learning (RL).

Octopus combines three co-designed mechanisms: (1) Zero-Copy Radix Forking, which spawns branches as $\mathcal{O}(1)$ cursor views over shared physical KV pages; (2) Attention-Only KV Mounting, which mounts a sibling thread's terminal KV blocks directly into full-attention layers while bypassing linear-recurrent states (Gated DeltaNet / Mamba-2), cutting off-task hijacking by $21\times$ ($57.9\% \to 2.7\%$) while retaining $92.2\%$ of full-text mutual information at zero extra KV allocation; and (3) a Packed DAG-GRPO Trainer, which packs all episode branches into one block-sparse attention pass and assigns counterfactual branch credit via leave-one-branch-out marginal rewards.
